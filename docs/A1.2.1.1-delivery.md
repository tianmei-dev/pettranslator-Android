## 声波问题与处理

原界面已经直接使用 `AudioRecord.read()` 返回的 PCM16。每次短读取统计样本平方和，得到真实 RMS，`RecordingViewModel` 将每个采集帧写入 `StateFlow` 最近 32 个值；没有发现 PCM 转换或状态更新被压扁。

显示映射是主要原因：旧实现先把 RMS 小于 `0.003` 的值归零，其余仅乘 6。0.003 约为 -50.5 dBFS；略高于该门限的输入映射也只有约 0.018，对应 64dp 画布不足 1.2dp，最后落在 2dp 基线。因此安静房间的真实声音常像一条虚线。录音刚开始时还会有 32 个历史空位，短截图只显示少数柱。

新实现只改变 UI 映射，原始 PCM 和采集线程不变：先计算 `dBFS = 20 × log10(RMS)`，低于 -65dBFS 的输入显示为基线；其余按 `clamp((dBFS + 65) / 55, 0, 1)^0.85` 映射到柱高。这个显示范围约覆盖 -65 到 -10 dBFS，不按整段录音自动增益；超过满量程的显示值限幅。每柱使用约 100ms 的线性过渡。仅 RECORDING 时接收帧和绘制实时幅度；静音没有随机波形，停止后改为静态基线。持续稳定的环境音会显示高度相近的柱，声音变化才会使柱高改变。

`WaveformLevelsTest` 验证静音门限、常见 RMS 范围、高音量限幅及 NaN/无穷值处理。Galaxy S10 真机截图中采集到一段安静环境输入，柱形明显高于基线且数值近似稳定。没有用受控扬声器信号做实验室式声压/频响校准；正常说话与宠物叫声的实际增益仍应在目标使用环境中人工试听确认，映射阈值可据此微调。
